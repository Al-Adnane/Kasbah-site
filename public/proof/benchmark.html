What Kasbah Guard Does

Kasbah Guard is a local-first data loss prevention (DLP) engine that runs on your machine. It intercepts, scans, and classifies data flowing through AI tools — clipboard content, file edits, and API calls — before anything sensitive leaves your device. It is not a cloud proxy. All processing happens locally on port 8788.

Methodology

How Self-Tests Work

Each test sends a predefined text payload through policy_findings() and the preflight scoring engine. The engine checks regex patterns, ML classification, and behavioral signals. A risk score (0-100) determines the decision: ALLOW (<30), WARN (30-49), CHALLENGE (50-69), REVIEW (60-69 with compliance triggers), or BLOCK (70+).

How Dataset Tests Work

Sample text is sent via POST /preflight or POST /ensemble/analyze. The response includes risk score, decision, and individual finding details. No pre-processing or cherry-picking is applied — the raw API response is recorded.

Scoring

Risk scores range from 0 to 100. They are computed from a combination of pattern match confidence, ML classification probability, behavioral signals (velocity, volume, time-of-day), and entropy analysis. The ensemble model weights these: pattern (0.4) + entropy (0.3) + semantic context (0.3).

Enterprise Features

UEBA Engine

Z-score anomaly detection, EMA risk scoring, per-user profiles, 8 behavior metrics, data movement tracking.

Compliance Engine

5 frameworks: GDPR, HIPAA, PCI-DSS, SOC 2, ISO 27001. Template activation, violation detection, remediation guidance.

RBAC + Fleet

5 roles from admin to viewer. Device registry. Currently single-device; fleet sync and cloud-based policy distribution are planned.

Process Monitor

Detects 15+ AI tools by process name. Monitors network egress. Flags suspicious ports. macOS only.

Cryptographic Audit

HMAC-SHA256 hash-chained ledger. Every decision is signed. Exports are signed. Tamper detection via chain verification.

Authority System

Cryptographic binding that proves YOU control what AI does on your machine. HMAC certificate tied to identity.

Known Limitations

We believe in honest assessment. Here is what Kasbah Guard does not do today:

  • No OCR or image scanning — Kasbah works on text content only
  • No network-level DLP — operates as a localhost service, not an inline proxy
  • No exact data matching (EDM) or document fingerprinting
  • No GPU-accelerated ML — uses CPU-based TF-IDF (fast but less powerful than deep learning models)
  • Single-device only — no cloud fleet synchronization yet (RBAC/Fleet is local)
  • Process monitor is macOS-only (uses ps aux and lsof)
  • No SAML/OIDC SSO integration
  • No DLP for email, Slack messages, or other SaaS channels
  • Clipboard monitor requires macOS accessibility permissions
  • ai4privacy obfuscated samples are not detected (by design — they contain no real PII)

How to Reproduce These Results

Every claim on this page is testable.
  1. Download the raw report: benchmark-v2.0.0.json
  2. Install Kasbah Guard v2.0.0 and run: curl http://127.0.0.1:8788/selftest/run
  3. Test PII detection: curl -X POST http://127.0.0.1:8788/classify -d '{"text":"SSN 284-37-5192"}'
  4. Test ensemble analysis: curl -X POST http://127.0.0.1:8788/ensemble/analyze -d '{"text":"SSN 123-45-6789"}'
  5. Verify audit chain: curl http://127.0.0.1:8788/audit/verify
  6. Test compliance: curl -X POST http://127.0.0.1:8788/compliance/check -d '{"text":"Patient SSN 284-37-5192"}'
  7. Source code: github.com/Al-Adnane/Kasbah-site
